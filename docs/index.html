iPhone-first Apple Music backup

Keep the map of your music.

Rekora is a local-first MVP for preserving the important details of an Apple Music library: saved music, playlists, playlist order, dates, and enough identifiers to rebuild what Apple Music allows.

The problem is not audio. It is memory.

Apple Music is a listening service, not a personal backup system. Rekora focuses on the library map: what a user saved, how playlists were arranged, which identifiers were available, and what changed over time.

The intended backup loop

The MVP is deliberately small: request permission, read useful MusicKit library data, save local snapshots, export user-owned backups, compare changes, and rebuild supported playlists only after a readable plan.

1

Ask permission

Use MusicKit authorization with clear denial and restriction states.

2

Read library data

Fetch playlists, songs, albums, order, and useful identifiers.

3

Save a snapshot

Write a protected local backup and latest-backup manifest.

4

Export and compare

Let users take their file out of the app and inspect changes.

5

Plan a rebuild

Separate matched, missing, unavailable, and uncertain tracks.

Portable backup contract

Schema v1 stores identifiers and fallbacks.

The schema is not the app database. It is the exported and imported backup format that should keep working even if local indexing later moves to SwiftData or SQLite.

Snapshot contents JSON
  • metadata schemaVersion, snapshotID, createdAt, and source app/platform details.
  • library items Saved songs, albums, and playlists with Apple identifiers where available.
  • fallbacks Title, artist, album, duration, track number, and disc number for records that may later lose catalog matches.
  • order Playlist entries keep playlistID, songID, MusicKit position, optional snapshotOrder, and optional addedAt.

Native first

Built where the library lives.

Rekora starts as an iPhone app with SwiftUI, MusicKit, versioned JSON backups, and XCTest. A Mac app, web dashboard, payments, accounts, cloud sync, and scheduled backups can wait until the basic MusicKit flow is trustworthy.

  • Bundle ID app.rekora.ios, pending Apple Developer portal alignment.
  • Privacy No external server storage is part of the MVP direction.
  • Limit Rekora backs up the library map, not audio files.

Functional completion is explicit.

Rekora is functionally complete only when a user can grant access, create a real local backup, export it, inspect changes, and rebuild at least supported playlists from that backup.
